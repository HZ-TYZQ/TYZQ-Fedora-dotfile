# Fedora dotfiles 操作指南

这份指南说明如何使用 chezmoi 和 Git 管理本仓库。目标是让 Git 仓库成为配置的
唯一长期来源，同时在每次部署前保留清晰的差异预览。

## 1. 先理解三个位置

本方案中同一份配置会涉及三个位置：

| 位置 | 作用 | 示例 |
| --- | --- | --- |
| 家目录 | 程序实际读取的配置 | `~/.config/niri/config.kdl` |
| chezmoi 源目录 | Git 管理的配置来源 | `~/.local/share/chezmoi/dot_config/niri/config.kdl.tmpl` |
| GitHub 仓库 | 远程备份与多设备同步 | `HZ-TYZQ/TYZQ-Fedora-dotfile` |

chezmoi 的“目标状态”是根据源目录计算出的、应该部署到家目录的内容。
`chezmoi diff` 显示目标状态与当前家目录之间的差异，`chezmoi apply` 才会把目标状态
写入家目录。

源目录中的名字看起来会有些特殊：

- `dot_config` 对应家目录里的 `.config`。
- `dot_gitignore` 对应 `.gitignore`。
- `private_` 表示目标文件或目录仅允许当前用户访问。
- `executable_` 表示目标文件应具有可执行权限。
- `readonly_` 表示目标文件应为只读文件。

这些前缀是 chezmoi 保存文件名和权限信息的方式，不要随意删除。

## 2. 当前仓库管理什么

当前纳管的是明确由用户维护的家目录配置：

- 桌面：Niri、Noctalia、Waybar、Swayidle、Swaylock。
- 终端和 Shell：Fish、Kitty、Starship。
- 工具：Neovim、Fastfetch、Yazi。Yazi 只纳管用户维护的部分：`init.lua`、
  `yazi.toml`、`keymap.toml`、`theme.toml`、`package.toml` 和自建插件
  `plugins/xdg-enter.yazi`。
- 系统集成：`environment.d`、XDG Portal 和用户自启动项。

以下内容有意不纳入仓库：

- `~/.config/yazi/flavors/noctalia.yazi`：Noctalia 社区模板 yazi 的输出路径，
  每次换主题/壁纸都会重写，纳管会让源目录与家目录反复分歧。
- `~/.config/yazi/plugins/smart-enter.yazi` 和 `plugins/fedora-clipboard.yazi`：第三方
  vendored 代码，版本由 `package.toml` 的 `rev`+`hash` 固定，用 `ya pkg install`
  即可还原，无需入库。旧版 `plugins/clipboard.yazi` 的排除规则也保留。
- `~/.pi/agent` 的全部内容：2026-09-21 已 `chezmoi forget` 退出纳管，改为纯本地维护。
- `.codex/auth.json`、`.grok/auth.json`、`.pi/agent/auth.json`。
- Pi Agent 的运行历史、模型缓存、npm 依赖、权限记录和其他未列入白名单的文件。
- `.ssh`、`.gnupg`、访问令牌、密码和 VPN 凭据。
- 日志、历史、会话数据库、缓存和下载内容。
- `/etc`、GRUB、DNF 和 Snapper 等系统级配置。
- Fish 的 `fish_variables`、Grok 自动补全等程序状态或生成内容。
- Noctalia 生成的 `niri/noctalia.kdl` 和 `kitty/themes/noctalia.conf`。
- `.bak`、迁移备份和实验副本。

本仓库公开可见，认证信息不能直接提交。即使改为私有仓库，也应继续排除凭据。

### Niri 配置分层

源目录中的 `dot_config/niri/config.kdl.tmpl` 只负责加载片段，chezmoi 将它渲染成
`~/.config/niri/config.kdl`。各文件的职责如下：

| 源目录中的文件 | 内容 |
| --- | --- |
| `conf.d/input.kdl` | 键盘布局、触控板和鼠标偏好 |
| `conf.d/appearance.kdl` | 平铺布局、截图路径、动画、模糊和光标 |
| `conf.d/rules.kdl` | 窗口与图层规则，保留原有先后顺序 |
| `conf.d/binds.kdl` | 快捷键，包括 Kitty、Noctalia 等应用操作 |
| `conf.d/session.kdl` | Fcitx5 环境变量、会话启动项及已禁用的备用组件 |
| `hosts/tyzq-fedora.kdl` | 本机内屏的接口、分辨率、刷新率和缩放 |

入口仅在 `.chezmoi.hostname` 为 `tyzq-fedora` 时加载对应的主机文件，其他机器
使用 Niri 自动选择的屏幕参数。新增机器或更改主机名时，在 `hosts/` 添加或调整
主机文件，并修改入口模板的选择条件。主机名匹配是显式配置，不会检测硬件型号。

`conf.d/` 不含固定屏幕型号，但会话、应用规则和部分快捷键仍依赖当前的
Niri + Noctalia 软件环境。输入和外观设置是可迁移的个人偏好。

Noctalia 自动生成的 `~/.config/niri/noctalia.kdl` 继续由 Noctalia 维护，并在入口
末尾加载，以保持原有配色覆盖顺序。该文件不纳入 chezmoi。

修改时优先编辑源目录中的片段；入口模板应直接修改 `config.kdl.tmpl`，不要用
`re-add` 将渲染后的入口回收到模板。部署前检查 `chezmoi diff --recursive ~/.config/niri`，
新增片段时先部署 `conf.d/` 和 `hosts/`，再部署入口，避免热重载遇到缺失的 include：

```bash
chezmoi apply ~/.config/niri/conf.d ~/.config/niri/hosts
chezmoi apply ~/.config/niri/config.kdl
niri validate -c ~/.config/niri/config.kdl
```

### Qt 配色路径

`dot_config/qt6ct/qt6ct.conf.tmpl` 使用 `{{ .chezmoi.homeDir }}` 生成当前用户的
Noctalia 配色路径，部署后仍为完整的绝对路径，不固定用户名。配色文件
`~/.local/share/color-schemes/noctalia.colors` 由 Noctalia 生成，不纳入仓库。

修改此配置时应直接编辑源模板，避免通过 `re-add` 将本机路径写回模板。

### 跨机器复用注意

只有需要由 chezmoi 计算的值才使用模板。Fish 和脚本中的 `$HOME`、程序自身
支持的 `~`、Neovim 的 `stdpath()` 已按运行环境解析，不需要重复模板化。

| 配置 | 迁移时如何处理 |
| --- | --- |
| Niri 屏幕参数 | 保留在 `hosts/`，按主机名加载，不让其他机器套用本机屏幕模式 |
| Qt 配色路径 | 模板按当前家目录生成；配色文件由 Noctalia 在本机生成 |
| Qt 的 `SettingsWindow.geometry` | 设置窗口的位置与尺寸，当前仍保留本机值，迁移时应按新屏幕调整 |
| Fish Rust 环境 | 仅在 `~/.cargo/env.fish` 存在时加载；Rustup 本身需另行安装 |
| 默认编辑器 | 设置为 `nvim`，从 PATH 查找，仍需安装 Neovim |
| KDE 自启动项 | 保留 KDE 会话限制，通过 `TryExec` 检查相应程序是否可执行 |
| `rpm-add` | 已使用 `$HOME`；需要 `createrepo_c`、本机 RPM 仓库目录及系统仓库配置 |
| Neovim Python 调试 | 路径由 `stdpath()` 获取；需要在 Mason 中安装 `debugpy`（`:MasonInstall debugpy`） |
| QQ 呼出脚本 | 适用于 Flatpak QQ、systemd 用户会话和支持 StatusNotifierItem 的托盘 |
| 字体、主题、快捷键 | 可复用的个人偏好，需要安装对应字体、图标、光标主题和应用 |

Noctalia 生成的 Niri 配色、Qt 配色和 Yazi 主题，以及由包管理器安装的 Yazi
插件，都不由本仓库直接部署。恢复到新机器时，应完成 Noctalia 初始化，并在
Yazi 中执行 `ya pkg install` 恢复 `package.toml` 固定的插件。

## 3. 在新安装的 Fedora 上恢复

### 3.1 安装工具

```bash
sudo dnf5 install git gh chezmoi
```

公开仓库的克隆无需登录。需要推送修改，或仓库日后改为私有时，先登录 GitHub：

```bash
gh auth login
gh auth setup-git
```

### 3.2 克隆，但先不应用

```bash
chezmoi init https://github.com/HZ-TYZQ/TYZQ-Fedora-dotfile.git
```

这个命令把仓库克隆到 `~/.local/share/chezmoi`，不会因为缺少 `--apply` 就立即覆盖
现有配置。

### 3.3 预览并应用

```bash
chezmoi status
chezmoi diff
chezmoi apply --dry-run --verbose
```

确认差异符合预期后再执行：

```bash
chezmoi apply
```

如果新机器已经存在同名配置，先另外备份这些文件。不要用 `--force` 跳过冲突检查。

### 3.4 应用后验证

```bash
niri validate
noctalia config validate ~/.config/noctalia
fish -n ~/.config/fish/config.fish
nvim --headless '+qa'
yazi --debug
```

桌面配置修改后，最好先验证，再按对应程序的方式重新加载。涉及环境变量和登录会话的
配置，通常需要注销后重新登录才能完全生效。

## 4. 日常修改：推荐流程

推荐直接编辑 chezmoi 中保存的版本：

```bash
chezmoi edit ~/.config/niri/config.kdl
chezmoi diff ~/.config/niri/config.kdl
chezmoi apply ~/.config/niri/config.kdl
niri validate
```

执行顺序是：

1. `edit` 修改仓库中的源文件。
2. `diff` 查看这次部署会改变什么。
3. `apply` 更新家目录中的实际配置。
4. 使用程序自己的检查命令验证配置。

对于风险很低的小改动，可以使用快捷方式：

```bash
chezmoi edit --apply ~/.config/starship.toml
```

桌面、登录、输入法和环境变量配置不建议省略独立的 `diff` 步骤。

## 5. 已经直接修改了 `~/.config` 怎么办

直接编辑家目录不会立即损坏仓库，但此时仓库版本与实际版本已经不同。

先检查差异：

```bash
chezmoi diff ~/.config/nvim/init.lua
```

确认要保留家目录里的修改后，将它重新收入源目录：

```bash
chezmoi re-add ~/.config/nvim/init.lua
chezmoi diff ~/.config/nvim/init.lua
```

第二次 `diff` 应该没有输出。尽量指定具体文件，不要习惯性执行不带路径的
`chezmoi re-add`，否则可能一次收录多项尚未检查的变化。

## 6. 提交并推送修改

进入 chezmoi 的 Git 仓库：

```bash
chezmoi cd
```

提交前依次检查：

```bash
git status
git diff
git diff --check
```

只暂存本次确认过的文件：

```bash
git add -- dot_config/niri/config.kdl
git diff --cached
git commit -m "config(niri): describe the change"
git push
```

不要使用 `git add .` 或 `git add -A`，它们容易把无关文件和意外生成的内容一起加入。

提交说明建议描述“什么行为发生了变化”，例如：

```text
config(niri): adjust overview animation
config(nvim): disable markdown spell checking
docs: document dotfile recovery workflow
```

## 7. 从远程同步更新

`chezmoi update` 会拉取远程提交并立即应用。日常确认没有本地未收录改动后，可以执行：

```bash
chezmoi status
chezmoi update
```

希望先拉取、检查、再应用时，使用更稳妥的分步方式：

```bash
chezmoi update --apply=false
chezmoi diff
chezmoi apply
```

如果 `chezmoi status` 或 `chezmoi diff` 在同步前已经有输出，先判断这些本地变化是否需要
通过 `chezmoi re-add <具体文件>` 保存，不要直接更新或强制覆盖。

## 8. 添加新的配置文件

先确认文件是稳定的手写配置，而不是凭据、缓存、日志或程序状态。然后执行：

```bash
chezmoi add ~/.config/example/config.toml
chezmoi managed ~/.config/example
chezmoi diff
```

添加整个目录前先查看其内容：

```bash
rg --files ~/.config/example
```

目录中只要混有凭据、缓存或自动生成文件，就应该逐个添加需要的文件，而不是直接添加
整个目录。

添加后进入仓库检查并提交：

```bash
chezmoi cd
git status
git add -- dot_config/example/config.toml
git diff --cached
```

`chezmoi add` 默认会进行秘密信息扫描，但它只能辅助检查，不能代替人工确认。

## 9. 停止管理某个配置

如果要让 chezmoi 停止管理某个文件，但保留家目录里的实际文件：

```bash
chezmoi forget ~/.config/example/config.toml
```

`forget` 删除的是 chezmoi 源状态中的条目，不会删除家目录中的目标文件。执行后检查并
提交对应的 Git 变化：

```bash
chezmoi cd
git status
git diff
```

如果目标是彻底删除实际配置，先单独确认程序影响和恢复方式；不要把 `forget` 当作删除
家目录文件的命令。

## 10. 处理差异和冲突

遇到冲突时先回答一个问题：要保留家目录版本，还是仓库版本？

### 保留家目录版本

```bash
chezmoi diff ~/.config/example/config.toml
chezmoi re-add ~/.config/example/config.toml
```

### 保留仓库版本

```bash
chezmoi diff ~/.config/example/config.toml
chezmoi apply ~/.config/example/config.toml
```

`apply` 可能提示目标文件已被修改。确认差异和备份后再允许覆盖，不要直接使用
`--force`。

### 两边都需要保留

先复制一份家目录版本作为临时备份，再运行：

```bash
chezmoi merge ~/.config/example/config.toml
```

`merge` 是三方合并：同时比较家目录、chezmoi 源状态和目标状态。本机当前没有配置专用
合并工具，因此复杂冲突更适合先备份，再手工编辑源文件并通过 `diff` 检查。

## 11. 回退错误修改

先查看仓库历史：

```bash
chezmoi cd
git log --oneline --decorate -20
```

恢复单个文件到旧提交：

```bash
git restore --source=<提交号> -- dot_config/niri/config.kdl
exit
chezmoi diff ~/.config/niri/config.kdl
chezmoi apply ~/.config/niri/config.kdl
niri validate
```

确认恢复正确后，把这次恢复作为新的提交推送。不要用 `git reset --hard` 回退整个仓库，
它可能丢弃尚未提交的其他配置修改。

初次迁移前的完整配置备份位于：

```text
~/Backup/chezmoi-pre-migration-20260821-235438.tar.gz
```

恢复该归档前应先查看归档内容并单独提取需要的文件，不要直接覆盖整个 `~/.config`。

## 12. 常用检查命令

```bash
# 显示已管理的目标
chezmoi managed

# 显示 ~/.config 下未管理的内容
chezmoi unmanaged ~/.config

# 查看状态和实际部署差异
chezmoi status
chezmoi diff

# 只做部署演练
chezmoi apply --dry-run --verbose

# 查看源仓库路径
chezmoi source-path

# 检查 chezmoi 环境
chezmoi doctor
```

## 13. 每次操作前后的简短清单

修改前：

1. 执行 `chezmoi status`，确认是否已有未处理变化。
2. 明确本次只改哪些文件。
3. 涉及桌面和登录配置时准备恢复方法。

修改后：

1. 执行 `chezmoi diff`。
2. 运行对应程序的配置验证。
3. 执行 `git status` 和 `git diff --cached`。
4. 只提交本次确认的路径。
5. 推送后确认本地分支与远程同步。

最重要的习惯只有一个：先看差异，再应用或提交。

## 14. 唯一来源与旧配置归档

自 2026-08-22 起，`~/.local/share/chezmoi` 是用户配置的唯一长期来源，家目录是
chezmoi 部署后供程序读取的结果。旧 `~/systemconfig` 中的 Niri、Noctalia、
自启动项等副本不再参与维护，避免两份配置逐渐产生差异。

旧目录归档于：

```text
~/Archives/systemconfig-legacy-20260822/
```

该归档还包含迁移备份、临时实验、VPN 资料和 Snapper/DNF 系统脚本，因此不得整体
加入 dotfiles 仓库。确认不再需要后由用户自行删除；删除前可先检查目录大小和所需
恢复资料。

系统级配置继续独立管理。chezmoi 不负责部署 `/etc`、GRUB、DNF 或 Snapper 设置，
也不通过自动脚本申请管理员权限。
